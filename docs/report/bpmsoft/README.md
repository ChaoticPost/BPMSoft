# Рабочая тетрадь: перенос доменной модели ProfIT в BPMSoft

Тетрадь для ручной реализации практики «Перекладывание доменной модели в объекты,
справочники, рабочие места, разделы и детали» на учебном стенде BPMSoft.

**Источник истины по модели** — `../domennaya/Domennaya model.puml`
(24 бизнес-сущности, 12 перечислений, 32 связи). Инварианты I-01–I-44 — из отчёта
практики № 2 (`../2-pr.typ`). Технический маршрут — презентация Снимщикова К. А.
и ТЗ `ProfIT_BPMSoft_полное_ТЗ_агенту_Chu_Chugunova_package.docx`.

## Порядок работ (фазы)

- **Фаза 0. Доступ и инвентаризация.** Войти, проверить шестерёнку «Дизайнер системы»,
  «Системные настройки», «Управление конфигурацией», «Мастер разделов», «Мастер деталей».
  Поиск в конфигураторе по `Contact`, `SysAdminUnit`, `SysUser`, `Account`, `Product`,
  `Role`, `Permission`, `Activity` — составить инвентарь штатных объектов
  (имя, код, пакет, можно ли расширять). Скриншот обзорной страницы.
- **Фаза 1. Настройки.** Издатель → `Чугунова`; пакет `Chugunova_package` → зависимость;
  «Текущий пакет» → `Chugunova_package`; «Префикс названия объекта» → `Chu`.
  Каждую настройку сохранить и переоткрыть для проверки. Скриншоты ×4–5.
- **Фаза 2. Справочники.** 12 справочников по `01-lookups.md`. Скриншот списка
  справочников и примера значений.
- **Фаза 3. Объекты.** 24 объекта + связка `ChuRolePermission` строго в порядке
  `02-objects.md` (порядок учитывает зависимости lookup). Для каждого:
  «Добавить → Объект» в пакете `Chugunova_package`, колонки по таблице,
  «Сохранить → Опубликовать», переоткрыть и проверить. Внимание: `ChuGameSession`
  создаётся в два прохода (см. файл). Скриншоты схем и карточек.
- **Фаза 4. UI.** Связи/детали/разделы/рабочее место по `03-links-ui.md`.
  Переименовать автосгенерированные схемы деталей и страниц + 3 привязки данных.
  Скриншоты мастера разделов, мастера деталей, рабочего места.
- **Фаза 5. Проверка и отчёт.** Тестовые данные по `04-testing-report.md`,
  негативные проверки, таблицы инвариантов, сборка Word-отчёта.

## Правила платформы (из презентации — соблюдать)

1. После каждого изменения объекта: **Сохранить → Опубликовать**. Не считать
   объект созданным, пока публикация не подтверждена.
2. У колонки два имени: **код** (только корректный английский перевод, не транслит)
   и **заголовок** (произвольный, по-русски). В тетради даны оба.
3. Удаление поля на странице ≠ удаление колонки из объекта. Поле, убранное со
   страницы, уходит в боковую панель «существующие колонки». Колонку из БД
   удаляют только в конфигураторе.
4. После регистрации детали мастер автогенерирует схему детали и страницу со
   случайными именами. **Переименовать до вывода на страницу**: у схемы детали и
   страницы убрать случайный фрагмент, оставив `prefix`/`detail`; плюс 3 привязки
   данных (`SysDetail_…`, `SysModuleEdit_…`, `SysModuleEntity_…`) — тип «Данные»,
   сортировка по дате создания.
5. Детали без кода: «со страницей добавления» и «с редактируемым реестром».
6. Расширять штатный объект — только **замещающим объектом** в `Chugunova_package`
   (конфигуратор → Добавить → Замещающий объект). Базовые пакеты не трогать.
7. Lookup-ссылка сама по себе **не гарантирует** кратность 1:1, XOR и «тот же
   родитель». Такие инварианты помечены в тетради как требующие процесса/проверки —
   в отчёте честно писать «требуется серверная проверка», а не «реализовано».
8. У объекта есть штатные `CreatedOn/ModifiedOn/CreatedBy` — не путать с доменными
   `createdAt/startedAt/...`: доменные колонки создаются отдельно, обе нужны.
9. Если при создании колонки платформа сообщает о существующем имени — не
   создавать дубликат, проверить и использовать существующую колонку.

## Как работать со скриншотами

- macOS: `Shift+Cmd+4` — выделенная область, `Shift+Cmd+5` — выбор места сохранения.
- На каждом скриншоте должны быть видны: название настройки/объекта, пакет/поле
  и результат действия. Пароль и чужие данные не фотографировать.
- Скриншоты складывать в папки `ProfIT_BPMSoft/01_Settings … 08_Issues`
  (см. `04-testing-report.md`) и присылать мне по мере этапов — я сверяю
  с моделью и помогаю заполнять отчёт.
