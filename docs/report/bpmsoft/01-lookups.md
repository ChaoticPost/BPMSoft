# Фаза 2. Справочники (12 перечислений UML → справочники BPMSoft)

Каждое UML-перечисление реализуется **справочником** (Lookup), а не строковым
полем. Системный дизайнер → «Справочники» → найти аналог по названию и коду;
если готового нет — создать свой с префиксом `Chu`.

## Как создать справочник

1. Дизайнер системы → «Справочники» → создать справочник.
2. Код справочника — `Chu…` (как в таблицах ниже), название — русское.
3. Если в справочнике нет колонки кода — добавить строковую колонку `Code`.
4. Записи: **Код** = точное значение enum (латиница, без изменений),
   **Название** = русское отображение из таблицы.
5. Сохранить, добавить все значения, проверить уникальность кодов.

> Сначала проверь, нет ли в системе готового справочника с теми же значениями
> (например, по статусам). Если есть и семантика совпадает — можно
> переиспользовать, но зафиксируй это в отчёте как «переиспользован штатный».
> По ТЗ ожидаются справочники `Chu…`.
